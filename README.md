# Assetto AI — Self-Driving Agent via Behavioral Cloning

An experiment in training a neural network from scratch to drive a car in **Assetto Corsa**, using only in-game telemetry (no computer vision) and **Behavioral Cloning** — the agent learns to drive by imitating a human driver's real inputs.

## Overview

The goal is to build an autonomous agent capable of completing laps on a track: staying within track limits, braking into corners, and accelerating on straights — using nothing but the game's shared memory telemetry as input and a recurrent neural network as the driving policy.

Unlike vision-based approaches, this project relies entirely on structured telemetry (speed, RPM, tire slip, G-forces, etc.) plus a set of custom-built track-relative sensors (lateral offset, heading error, upcoming curvature) computed from a reconstructed racing line.

## How it works

1. **Data collection** — A human drives laps with a physical wheel while telemetry (via shared memory) and driver inputs are recorded at ~90Hz.
2. **Cleaning** — Invalid samples (off-track excursions, corrupted frames, negative RPM, etc.) are filtered out.
3. **Track feature engineering** — The recorded positions are used to reconstruct a smoothed racing line. From it, the pipeline derives per-frame sensors: lateral position relative to the line, heading error, curvature at several lookahead distances (0–50m), and speed error relative to a safe cornering speed.
4. **Synthetic augmentation** — Additional training samples are generated by simulating the car being displaced from the ideal line, paired with a corrective steering action. This mitigates the classic Behavioral Cloning failure mode (distribution shift / covariate shift), where a model trained only on near-perfect driving has never learned how to recover from small errors.
5. **Training** — A GRU-based recurrent model is trained on sequences of frames, so the policy has short-term temporal context instead of reacting to a single instantaneous frame.
6. **Real-time inference (autopilot)** — The trained model reads live telemetry, computes the same track sensors used in training, and sends steering/throttle/brake commands to the game through a virtual joystick (vJoy).

## Model

- **Type:** GRU (recurrent neural network) with 3 output heads
- **Input:** sequence of the last N frames, 35 features per frame (car telemetry + track sensors)
- **Output:** steering (Tanh, [-1, 1]), throttle (Sigmoid, [0, 1]), brake (Sigmoid, [0, 1])
- **Regularization:** dropout, weight decay, early stopping on validation loss

### Input features

| Category | Features |
|---|---|
| Car dynamics | speed, RPM, gear, G-forces (x/y/z), local & angular velocity |
| Tires | slip (FL/FR/RL/RR), tire temperature (FL/FR/RL/RR) |
| Track state | lap progress, sector, surface grip, tyres out |
| Track-relative sensors | heading error, lateral position, curvature (0–50m ahead), curve direction, speed error, arc-length position (`s_current`) |

## Project structure

```
.
├── lib/                      # dataset storage
├── recorder.py                # records telemetry + human driver inputs during data collection
├── telemetry.py                # shared-memory telemetry reader
├── clean_dataset.py            # filters/cleans the raw recorded dataset
├── inspect_dataset.py          # dataset inspection utilities
├── inspect_anomalies.py        # detects anomalous samples in the dataset
├── analyze_dataset.py          # dataset analysis / statistics
├── build_track_features.py     # reconstructs the racing line and computes track sensors (offline, for training data)
├── augment_dataset.py          # generates synthetic recovery samples (perturbation-based augmentation)
├── train_model.py              # trains the feedforward (MLP) model
├── train_model_gru.py          # trains the GRU (recurrent) model
├── test_model.py               # evaluates a trained model against real driving data
├── test_vjoy.py                # utility for testing the virtual joystick output
├── autopilot.py                # real-time inference loop — drives the car using the trained model
├── recovery_logger.py          # logs track sensors during autopilot runs, for debugging recovery behavior
├── analyze_recovery_log.py     # plots/analyzes recovery logs (e.g. around off-track events)
├── main.py                     # entry point / orchestration
├── input_reader.py             # reads physical wheel input during data collection
└── requirements.txt
```

## Status

**Working:**
- Full pipeline from raw telemetry capture to real-time autonomous driving is functional end-to-end.
- The agent can drive autonomously for most of the track, staying within limits most of the time and handling both corners and straights.
- Automatic pit takeoff, safety braking (curvature-based), and a manual recovery controller (for when the car drifts too far from the racing line) are implemented.

**Known issues / in progress:**
- Residual steering oscillation ("zigzag") on straights, more noticeable right after leaving the starting grid.
- Currently investigating a shared-state bug between the recovery controller and the model's inference loop: both write to the same smoothing/rate-limiting variables, so a brief, unlogged recovery event can leave the steering command "contaminated" when control hands back to the model.
- Cornering precision in tighter corners still needs improvement.
- Generalization to other tracks/cars has not been tested yet.
